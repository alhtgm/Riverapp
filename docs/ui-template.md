# River UI テンプレート — 分かりやすさ優先

新しい画面を作るとき・直すときは、この決まりと `src/components/ui/kit.tsx` の部品を使う。

## 5つの原則

1. **見出しには一言の説明を添える**
   `Section` の `description` に「何をする場所か／押すとどうなるか」を1文で書く。
2. **主な操作は1か所に1つ**
   オレンジ（`variant="primary"`）はそのまとまりで一番押してほしいボタンだけ。ほかは `secondary` / `ghost`。
   ボタンを2つ並べるときは「取り消し側を左・進める側を右」にする（例：拒否｜承認）。
3. **空の状態では次にやることを示す**
   一覧が空のときは `EmptyState` を使い、`description` に「こうすると増えます」を書く。
4. **取り消せない操作は必ず確認を挟む**
   削除・退出・ブロック・解除・投票開始などは `Confirm` を出す。`detail` に「押すと何が起きるか」と「元に戻せるか」を書く。
5. **見た目をそろえる**
   余白（4・8・12・16・24px）、角丸（ボタン10px／カード12px）、ボタンの高さ（通常38px／小30px）、
   文字（見出し14px・本文13〜14px・補足11〜12px）を統一する。

## 画面の組み立て方

```
Sheet（タイトル＋subtitle に画面の説明）
 ├─ Tabs（画面内の切り替え。未対応の件数は badge）
 ├─ Section（見出し＋説明＋右上の操作）
 │    └─ List > ListItem（アイコン｜名前・補足｜右端の操作）
 ├─ Section
 │    └─ Field（ラベル＋必須/任意＋入力欄＋補足）… Button(primary)
 └─ Section（危険な操作は最後に）
      └─ Confirm
```

## 部品

| 部品 | 使いどころ |
|---|---|
| `Sheet` | モーダル。`subtitle` で画面の目的を書く。タブがある画面は `height` を指定して高さを固定 |
| `Tabs` | 画面内の切り替え。対応が必要な件数は `badge` |
| `Section` / `SectionHeader` | 見出し＋説明。`count` で件数を添える |
| `List` / `ListItem` | 人・パーティー・通知・申請などの一覧。行を押すと詳細へ（`onClick`）、右端に操作（`trailing`） |
| `Card` | 中身をまとめる箱。`tone="muted"` は背景をなじませたいとき |
| `Field` | 入力欄のラベル。必須か任意かを必ず表示。中身がボタンを含む部品なら `group` |
| `Button` | `primary` は1つだけ。処理中は `loading` |
| `Badge` | 状態（フレンド・申請中・投票中など）と件数 |
| `Notice` | 画面の前提や注意点（例：設定は誰でも変更でき履歴に残る） |
| `EmptyState` | 一覧が空のとき。次の一歩を書く |
| `Confirm` | 取り消せない操作の前の確認 |
| `Avatar` | 名前の頭文字アイコン |
| `LectureCard` | 講義の表示（講義名／年度・学期／担当教員／参加・公開範囲・参加申請） |

## 言葉づかい

- ボタンは「動詞」で終える：「参加する」「招待する」「保存する」「元に戻す」。
- 結果はトーストで伝える：「〇〇に参加しました。課題がタイムラインに追加されます」のように、次に何が起きるかまで書く。
- 専門用語は使わない（「RLS」「アーカイブ」などは画面に出さず、「誰からも見えなくなります」と書く）。
